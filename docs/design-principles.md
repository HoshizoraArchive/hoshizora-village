# 星空Village デザイン原則

この文書は、星空Villageに新しい画面・機能・言葉・色・演出を追加するときの判断基準を定める。

現在のUIを一律に作り直すための文書ではない。既存UIは、実際の利用状況やユーザーの反応から問題が確認されたときにだけ変更する。

## 1. 命名の二層構造

星空Villageの言葉は、次の二層で構成する。

### 世界観語

村の文化、体験、感情、行為を表す言葉。

例：

- 観測
- 流星便
- 共鳴
- 星文

日本語を中心に、やわらかく物語性のある言葉を使う。

### システム語

村を支える接続、整理、個人空間などの機構を表す言葉。

例：

- Re:Connect
- Archive
- My Const.

英字・略称・記号を含む、少し構造的で近未来的な言葉を使える。

### 命名ルール

- 日本語と英語が混在すること自体は問題としない。
- 新しい名称は、世界観語かシステム語かを意識して決める。
- 同じナビゲーション内では、名称の粒度を揃える。
- 固有名詞の並びに、一つだけ説明文や操作命令を混ぜない。
- 現在のボトムナビは `観測 / Re:Connect / 流星便 / Archive / My Const.` を基準とする。

## 2. 二層を見せる視覚文法

世界観語とシステム語は、別のサービスに見せるのではなく、同じVillageの「文化」と「機構」として見せる。

### 共通にするもの

- 文字サイズ
- 基本のフォントウェイト
- 配置
- 余白
- 選択状態
- 操作感
- アクセシビリティ

### 差を出してよいもの

- アイコンのモチーフ
- 線の柔らかさ
- 字間の微調整
- 装飾の質感

世界観語には星、手紙、光、観測などの有機的・物語的なモチーフを使える。

システム語には接続、座標、星座、保存、構造などの幾何学的・機構的なモチーフを使える。

説明文を読まなければ理解できない差にはしない。見た瞬間に同じ世界の二層として感じられることを優先する。

## 3. セマンティックカラー

操作や状態を伝える色は、意味を固定して使う。

- 水色：主要操作、選択中、リンク、通常の強調
- 紫：補助的な強調、AI、幻想的な要素
- ピンク〜赤：削除、失敗、危険な操作
- 黄色〜アンバー：注意、管理者、特別な権限
- 白〜グレー：通常情報、補足、非活性

正確な色コードは実装上のデザイントークンで管理するが、意味は画面ごとに変えない。

装飾目的で意味色を使い回さない。危険操作の色を華やかさだけのために使用しない。

## 4. ブランドカラー

水色〜紫〜ピンクの星空グラデーションは、セマンティックカラーとは別の「ブランドカラー」として扱う。

ブランドカラーは、星空Villageそのもの、流星、放流、特別な瞬間を表す。

- 成功、警告、削除などの状態表示には使わない。
- 通常の主要ボタンすべてには使わない。
- 一画面に複数の強いブランドグラデーションを置かない。

## 5. 特別使用ルール

ブランド演出や特別フレームは、役割が明確な場所にだけ使用する。

### 使用を認める代表例

- 中央の流星便CTA
- 星空ちあなど、公式のAI住人・案内人
- 入村、放流、達成などの象徴的な場面
- 星空Village全体を代表する画面や演出

中央の流星便CTAは、放流の入口としてブランドグラデーションを使える特別なCTAとする。

AI住人や案内人の特別表示は、一般ユーザーとの差を示す公式性・役割に基づいて行う。単に目立たせたいという理由だけでは使わない。

## 6. やらないこと

- 意味のない色分け
- 画面ごとに独自の命名ルールを増やすこと
- 新しい固有名詞を、世界観語かシステム語か決めずに追加すること
- すべての主要ボタンへブランドグラデーションを使うこと
- 「可愛いから」という理由だけで装飾や色を増やすこと
- 分かりにくいUIを、長い説明文だけで補うこと
- 世界観語とシステム語を、別サービスに見えるほど強く分離すること

星空Villageのデザインは、「なんとなく可愛い」ではなく、村の文化・観測システム・操作の意味が一つの世界として伝わることを基準に判断する。
